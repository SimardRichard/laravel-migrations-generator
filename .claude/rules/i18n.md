# Localisation (i18n) — module Language

## Langues supportées
- Reference Model `Language` (code ISO 639-1, label_fr, label_en, is_active, is_rtl)
- Seeder par défaut : `fr`, `en` (actives). Autres langues désactivées par défaut.
- Admin peut activer/désactiver via interface

## Par utilisateur
- `Profile.language_id` (FK vers `languages`)
- `Profile.timezone` (ex: `America/Toronto`)
- Middleware `SetUserLocale` configure `app()->setLocale()` et `Carbon::setLocale()` à partir du Profile

## Dates et heures
- Stockage **toujours en UTC** en BD
- Affichage dans le fuseau du Profile via `$date->setTimezone($user->profile->timezone)`
- Format selon la locale : `$date->translatedFormat($format)`

## Nombres et monnaies
- Utiliser `NumberFormatter` PHP avec la locale user
- Money Value Object fait déjà `formatted(locale)` correctement (fr_CA vs en_CA vs fr_FR etc.)

## Traductions
- Fichiers `app/Modules/{M}/lang/{code}/*.php` chargés avec namespace du module :
  ```php
  trans('facturation::messages.saved')
  trans('facturation::validation.amount_required')
  ```
- **Jamais de string hardcodée** dans les messages d'erreur, emails, notifications
- Clés en snake_case, organisées par domaine (messages, validation, mail, notifications)

## Directionnalité RTL
- Colonne `is_rtl` sur Language
- Middleware ajoute la classe CSS `dir-rtl` quand la langue active l'est
- Filament admin : layout adapté automatiquement

## Ajouter une nouvelle langue
1. Seed `Language::create(['code' => 'es', 'label_fr' => 'Espagnol', 'label_en' => 'Spanish', 'is_rtl' => false, 'is_active' => false])`
2. Traduire chaque module : `app/Modules/{M}/lang/es/` (copie de `fr/` puis traduction)
3. Admin active via `Language.is_active = true`
